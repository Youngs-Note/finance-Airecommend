# 프론트엔드 교체 후 연동 검토

## 결론

팀원이 교체한 `front/`의 새 UI는 사용할 수 있다.
새로 추가된 마이페이지와 로그아웃 화면은 유지하고, 기존 백엔드 연동 규칙에 맞지 않게
되돌아간 부분은 다시 연결했다.

## 복구한 연동

- 사용자 저장소를 SQLite에서 로컬 MySQL `app_users`로 복구
- 금융상품 목록, 상세, 비교 요약, 금리 통계, 추천을 FastAPI 실시간 조회로 복구
- CSV 금융상품 시드와 활성 SQLite 마이그레이션 제거
- 로그인 비밀번호 콘솔 출력을 제거하고 로그인 완료 후 홈 이동을 안정화
- 홈의 가상 상품과 금리 표시를 공식 상품 비교 진입 화면으로 교체
- NextAuth 공통 설정과 `NEXTAUTH_URL` 로컬 기본값 추가

## 새 UI에서 유지한 부분

- 마이페이지 프로필 화면
- 로그아웃 버튼
- 내 정보 수정과 비밀번호 변경 화면의 진입 경로

내 정보 수정과 비밀번호 변경은 아직 저장 API가 없으므로, 성공한 것처럼 표시하지 않고
준비 중인 비활성 화면으로 명확히 표시한다.

## 검증 결과

- `npm run lint` 통과
- `npm run build` 통과
- FastAPI, MySQL, 금융감독원 API, NextAuth 로그인 세션 통합 스모크 테스트 통과
- OpenAI 호출은 로컬 설정에서 비활성화하고 규칙 기반 설명 fallback 사용

## 남은 항목

- 내 정보 수정 API와 비밀번호 변경 API 구현
- `npm audit`의 moderate 항목 7건은 호환 가능한 상위 수정 버전 공개 시 재점검
