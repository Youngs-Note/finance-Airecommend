# 금융상품 데이터 출처와 은행 범위

## 데이터 출처

금융감독원 `금융상품 한눈에` 오픈 API의 은행 권역 코드 `020000`을 사용한다.
예금과 적금 응답은 요청 시점에 메모리에서만 정규화한다.
배포 환경에서 외부 API 호출이 실패할 수 있어 정규화된 캐시 파일을 함께 제공한다.

캐시 파일:

```text
backend/app/data/finlife_products.json
```

## 포함 범위

특수은행, 지방은행, 저축은행, 외국은행 국내 지점을 제외한다.
지정 시중은행과 인터넷전문은행만 노출한다.

허용 기관:

| 분류 | 기관 |
| --- | --- |
| 시중은행 | KB국민은행, 신한은행, 우리은행, 하나은행, SC제일은행, 한국씨티은행 |
| 인터넷전문은행 | 케이뱅크, 카카오뱅크, 토스뱅크 |

금융감독원 API의 `kor_co_nm` 표기와 은행연합회 표기가 다를 수 있어 코드에는 동일 기관의 표기
별칭도 함께 둔다. 별칭은 새로운 기관을 허용하기 위한 값이 아니다.

## 제외 범위

| 분류 | 예시 |
| --- | --- |
| 특수은행 | 한국산업은행, 중소기업은행, 농협은행, 수협은행 |
| 지방은행 | iM은행, BNK부산은행, 광주은행, 제주은행, 전북은행, BNK경남은행 |
| 저축은행 | 권역 코드 `030300` 전체 |
| 외국은행 국내 지점 | 은행 권역 응답에 포함될 수 있는 외국은행 지점 |

## 실제 인증키 연결 확인

2026-06-02에 개인 인증키로 실제 `020000` 예금·적금 응답을 확인했다.
허용 기관의 API 표기를 검증하고 `주식회사 하나은행` 별칭을 반영했다.
특수은행 예시는 허용 목록 필터 후 노출되지 않는 것을 확인했다.

2026-06-03에 노출 범위를 좁혀 지방은행을 허용 목록에서 제거했다.
실제 API 응답을 다시 확인하여 지방은행 상품이 노출되지 않는 것을 검증했다.

2026-06-08에 Render 배포 환경에서 Finlife API 호출이 실패하는 상황을 확인했다.
알파 테스트에서 샘플 상품명이 노출되지 않도록 로컬에서 공식 API 응답을 다시 수집해
`backend/app/data/finlife_products.json` 캐시 파일로 저장했다.
캐시는 공식 API 응답을 정규화한 결과이며, API 응답 원문과 인증키는 저장하지 않는다.

2026-06-08 기준 캐시에는 허용 기관 범위의 예금·적금 32개 상품이 포함된다.
캐시 데이터는 생성 시점 기준이므로 최신 금리 확인이 필요한 경우 공식 상품 설명을 다시 확인해야 한다.
